# Туту MCP на Python

Локальный прототип поиска прямых железнодорожных билетов на живом Туту. Сервер, MCP-клиенты, тесты и диагностические скрипты переписаны на **Python 3.11+**. Приложению больше не нужны Node.js, npm, TypeScript и сборка JavaScript.

Пользователь → агент Codex → собственный MCP → Playwright → публичный Туту. Агент понимает русский запрос, переводит даты и сравнивает пожелания по [AGENTS.md](AGENTS.md). Сервер предоставляет три предметных инструмента и возвращает нормализованные данные. Отдельный ключ API серверу не нужен.

## Установка и запуск

Нужны Python 3.11+ и Google Chrome. Виртуальное окружение и локальная конфигурация не хранятся в Git. После клонирования:

```sh
git clone https://github.com/ogwayz/tutu-mcp.git
cd tutu-mcp
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.smoke
```

`requirements.lock` фиксирует точные версии всех зависимостей, включая тестовые. Проверенная среда — macOS, Python 3.11.5, MCP SDK 2.3.0, Playwright 1.65.2, Pydantic 2.14.4. `pyproject.toml` описывает пакет и прямые зависимости; для воспроизведения проверки используйте lock-файл.

Запуск сервера:

```sh
.venv/bin/python server.py
```

Он ждёт MCP-клиента на stdin. Приветствия и обычного интерфейса нет: stdout занят JSON-RPC, диагностика идёт в stderr. Codex самостоятельно запускает этот процесс, вручную держать терминал открытым не требуется.

По умолчанию используется установленный Chrome с временным профилем. Личный профиль не подключается. Если Chrome отсутствует:

```sh
.venv/bin/python -m playwright install chromium
BROWSER_CHANNEL=chromium .venv/bin/python server.py
```

Видимый режим: `HEADED=1 .venv/bin/python -m scripts.live`. TLS-проверка включена, капчи и ограничения доступа не обходятся. Сам Playwright использует собственный браузерный драйвер; JavaScript в `evaluate` исполняется внутри страницы для чтения DOM. Бизнес-логика и MCP работают на Python, отдельной Node.js-реализации в проекте нет.

## Подключение к Codex

Создайте `.codex/config.toml`, скопировав пример ниже. Замените `/ABSOLUTE/PATH/tutu-mcp` на полный путь к вашей папке проекта:

```toml
[mcp_servers.tutu-trains]
command = "/ABSOLUTE/PATH/tutu-mcp/.venv/bin/python"
args = ["/ABSOLUTE/PATH/tutu-mcp/server.py"]
startup_timeout_sec = 20
tool_timeout_sec = 180

[mcp_servers.tutu-trains.env]
BROWSER_CHANNEL = "chrome"
USER_TIMEZONE = "Europe/Moscow"
HEADED = "0"
```

Откройте новый чат Codex в этой папке либо перезапустите MCP-подключение: уже работающий чат может сохранять старый процесс. `codex mcp list` должен показывать Python в поле Command. Проект должен быть доверенным для загрузки проектной конфигурации. AGENTS.md задаёт поведение агента.

Для других проектов скопируйте блок из `codex-config.example.toml` в `~/.codex/config.toml`, сохранив остальные настройки. Не создавайте дублирующиеся блоки одного имени. На другом компьютере замените абсолютные пути. Инструкции AGENTS.md из этого проекта автоматически не распространяются на другие папки.

Точка входа `server.py` работает независимо от текущего каталога: Codex запускает её по абсолютному пути. При желании пакет можно установить через `pip install .` и запускать `tutu-trains`, но для текущего подключения установка пакета не требуется.

## Инструменты

| Инструмент | Параметры | Результат |
|---|---|---|
| search_trains | origin, destination, departure_date: YYYY-MM-DD | Нормализованные станции, прямые поезда, вокзалы, даты/время, длительность, категории вагонов, количество, цены от, источник и checked_at |
| get_train_seats | result_id | Перечень вагонов выбранного поезда, типы, доступное количество, услуги |
| get_carriage_seats | result_id, carriage_number | Раскрытая схема вагона, только свободные номера, полки, подтверждённая группа купе, обычная взрослая цена, класс и ограничения |

Имена и основной формат результатов сохранены при переходе с TypeScript. Третий инструмент нужен для открытия конкретного вагона: агент сначала получает перечень, затем выбирает вагоны для подробной проверки.

UUID result_id хранится в памяти и связывает поезд, дату и участок. Срок — 15 минут; время жизни считается монотонными часами. Перезапуск аннулирует UUID. При STALE_RESULT повторите поиск. Запросы выполняются последовательно под asyncio.Lock; каждый вызов использует новый контекст браузера. Контексты закрываются после вызова, браузер — при EOF, SIGINT или SIGTERM.

## Примеры запросов

- «Москва — Санкт-Петербург на 15 декабря 2026 года, купе, нижнее место до 6000 рублей».
- «Москва — Казань завтра, отправление после 18:00, покажи до пяти вариантов».
- «Найди два места в одном купе из Москвы в Петербург на 15 декабря 2026 года. Проверь номера и обычную цену».

Даты примеров со временем устареют. Относительные даты агент переводит с учётом текущей даты и часового пояса пользователя. Сервер проверяет существование даты и прошедшие дни; причину закрытой продажи определяет только по сообщению Туту.

## Качество данных и ограничения

Все предложения читаются с живого сайта. Тестовые снимки никогда не используются при поиске. Станции и даты — параметры, маршруты в адаптере не зашиты. Точное совпадение подсказки выбирается автоматически; при неоднозначности возвращается список вариантов. Отсутствие загрузки не означает отсутствие мест.

Список поездов догружается прокруткой максимум 20 порций. Прекращение роста не доказывает полноту: `listing_complete=null` с предупреждением. При достижении лимита — false. Карточки с несколькими участками не выдаются как прямые поезда. Проходящий поезд с нужным участком допустим. Пересадки не подбираются.

Место считается свободным только при DOM `data-ti-state=active`; номера со статусом sold_out исключаются. Полка определяется по `data-ti-type=bottom/top`, а не по чётности номера. Количество сверяется с карточкой вагона: несоответствие вызывает SITE_CHANGED.

Купе, класс и цена связываются с группами мест из публичного `#__NEXT_DATA__.props.pageProps.initialState.dictionaries`. Это **недокументированная структура страницы**, проверяемая Pydantic. Прямых запросов к выдуманным или внутренним API нет. При изменении структуры потребуется обновить адаптер.

Цена места — `price.total` для взрослого пассажира type=0, обычного fareType=0, без fareDiscounts. Детские и условные платёжные скидки исключаются; при неоднозначности цена null. Минимальная цена вагона не распространяется на каждое место. Поиск возвращает price.kind=from с неизвестными условиями скидки. При сравнении бюджета агент использует цену конкретного места. Копейки сохраняются; на экране сайта цена округлена вверх до рубля.

Пол купе и этаж пока возвращаются null: коды не интерпретируются без проверки для конкретных схем. Нельзя обещать одно купе в двухэтажном вагоне без подтверждённого этажа. Некоторые сидячие схемы возвращают position=unknown. Проверка двух маршрутов не доказывает поддержку каждого перевозчика и каждой схемы Туту.

Часовой пояс выдачи — null, если сайт его не установил. Подробная страница возвращает UTC и IANA-зоны участка. Переход даты при ночной поездке сохраняется. Каждый ответ имеет checked_at; цена и наличие могут меняться между вызовами и до оформления.

Различаются INVALID_DATE, PAST_DATE, STATION_NOT_FOUND, AMBIGUOUS_STATION, SALES_NOT_OPEN, NO_DIRECT_TRAINS, SOLD_OUT, SITE_UNAVAILABLE, BLOCKED, TIMEOUT, SITE_CHANGED, STALE_RESULT. Причина не угадывается. Автоматических бесконечных повторов нет.

Нет покупки, создания заказов, бронирования, паспортных и платёжных данных, постоянного мониторинга, пересадок, Telegram-бота и отдельного веб-интерфейса.

## Проверки

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.smoke
.venv/bin/python -m scripts.live
.venv/bin/python -m scripts.verify_ui
```

`smoke` запускает отдельный Python-процесс через официальный MCP-клиент, получает listTools, проверяет входную валидацию и ошибки даты/UUID. `live` вызывает все три инструмента для Москвы — Санкт-Петербурга и Москвы — Казани, затем проверяет фильтр нижних до 6000 ₽. По умолчанию дата — текущий московский день + 20 дней. Можно задать `LIVE_DATE=2026-12-15`.

`verify_ui` сверяет три доступных места и обычные цены с интерфейсом в одной сессии; выбирает/снимает выбор на схеме, не нажимает «К пассажирам». Отчёты: artifacts/python-live.json, artifacts/python-ui-verification.json и снимки python-ui-seat-*.png. [Результаты проверки](docs/live-verification.md).

## Файлы

- `server.py`, `tutu_mcp/server.py` — запуск, MCP и входная валидация;
- `tutu_mcp/tutu.py` — адаптер и все локаторы;
- `tutu_mcp/browser.py` — браузер, изоляция и очередь;
- `tutu_mcp/models.py`, `parsers.py`, `errors.py` — типы, нормализация и ошибки;
- `scripts/` — Python MCP-клиент, smoke, live и визуальная сверка;
- `tests/` — pytest и исторические тестовые снимки;
- `requirements.lock`, `pyproject.toml` — зависимости;
- `AGENTS.md`, `codex-config.example.toml` — инструкция агенту и подключение.

Официальная документация: [MCP Python SDK](https://py.sdk.modelcontextprotocol.io/), [Playwright Python](https://playwright.dev/python/docs/library), [Codex MCP](https://developers.openai.com/codex/mcp/).
